\section{Outline of the Software Being Tested}

PizzaDronz is a Spring Boot REST API managing autonomous pizza delivery drones. The system validates orders (credit cards, restaurant menus, dates), calculates collision-free paths using A* pathfinding avoiding no-fly zones, and outputs GeoJSON visualizations. Core components: LngLatService (Euclidean distance, proximity, region containment via ray-casting); OrderValidationService (business rules, 604 real orders); AStarPathFinding (optimal obstacle avoidance); GeoJsonUtils (path formatting). External REST endpoints provide restaurant data, no-fly zones, and orders.

\section{Learning Outcomes}
\begin{enumerate}
\item \textbf{Analyze requirements to determine appropriate testing strategies} \marginpar{[default 20\%]}
\begin{enumerate}
\item \textbf{Requirements range}: Functional (Euclidean distance, credit card validation with Luhn algorithm, pathfinding avoiding no-fly zones); Quality attributes (performance: <60s pathfinding timeout, accuracy: $\pm$0.00015 epsilon tolerance, reliability: 100\% pass rate across 871 tests); Qualitative (safety: no-fly zone avoidance via property assertions, usability: clear validation error codes).

\item \textbf{Testing levels}: Unit (218 tests) validate LngLatHandling methods using boundary analysis at MIN/MAX coordinate limits and testing 16 compass directions. Integration (41 tests) verify PathFinding invoking LngLatService for distance checks while avoiding obstacles. System tests use @MethodSource fetching 604 real orders from REST API, validating end-to-end workflows including restaurant lookups and price calculations.

\item \textbf{Test approach}: Boundary value analysis tests coordinate system limits critical for preventing out-of-bounds errors. Equivalence partitioning divides inputs (valid, below minimum, above maximum) reducing test combinations. Property-based testing asserts path invariants (start/end positions, no-fly zone avoidance, central region constraints, consistent step distances) providing stronger guarantees than examples. Random testing (@RepeatedTest(20)) generates diverse inputs detecting edge cases.

\item \textbf{Appropriateness}: Extensive boundary testing (218 tests) ensures mathematical robustness at precision limits. 604 real orders provide realistic validation impossible to construct manually. Property assertions catch entire bug classes rather than individual instances. However: only 49 geographical positions tested versus thousands needed for statistical confidence; no concurrent testing despite REST API nature; no fault injection for network failures; controller layer untested due to Spring Boot context conflicts.
\end{enumerate}

\item \textbf{Design and implement comprehensive test plans with instrumented code} \marginpar{[default 20\%]}
\begin{enumerate}
\item \textbf{Test plan structure}: Hierarchical organization via @Nested classes: LngLatHandlingTests (7 nested groups), OrderValidationTests (@TestInstance(PER\_CLASS) with @BeforeAll loading REST data once), PathFindingTests (@ParameterizedTest with @MethodSource streaming restaurants), PathCalculationAsGeoJsonTests (output validation), ControllerTests (endpoint logic). Employs parameterized testing, boundary analysis, state-based validation, and data-driven testing.

\item \textbf{Plan quality}: Strong organization through @DisplayName annotations and logical @Nested grouping providing clear traceability. 871 tests with good independence via proper lifecycle management. Weaknesses: no explicit coverage criteria documentation (only in pom.xml); missing test prioritization (slow 23.5s PathFindingTests alongside fast 0.21s ControllerTests); REST dependencies create brittleness; limited error path coverage (happy path focused).

\item \textbf{Instrumentation}: Custom assertion messages ("Longitude mismatch for direction: " + direction) enable quick debugging. ExecutorService with Future.get(60, TimeUnit.SECONDS) instruments timeouts. SystemConstants.EPSILON\_ERROR standardizes floating-point comparisons. RestTemplate instruments integration points. Property assertions validate path correctness (start/end positions, no-fly avoidance, step consistency). Maven Surefire JUnit 5 reporters generate CI-consumable XML.

\item \textbf{Instrumentation evaluation}: JaCoCo measures 85\% instruction, 90\% branch (exceeding 75\% target), 81\% line coverage (below 80\% target due to 0\% controller coverage). Timeout instrumentation catches regressions. Epsilon assertions prevent flakiness. Critical gaps: no mutation testing (assertion quality unmeasurable); ad-hoc System.out.println logging versus structured frameworks; per-test timing unrecorded; no memory profiling; concurrent execution scenarios lack instrumentation.
\end{enumerate}

\item \textbf{Apply a wide variety of testing techniques and compute test coverage and yield according to a variety of criteria} \marginpar{[default 20\%]}
\begin{enumerate}
\item\textbf{Techniques}: (1) Boundary Value Analysis (MIN\_LNG/-3.192473, MAX\_LNG/-3.184319, angle 0-360°); (2) Equivalence Partitioning (valid/invalid coordinate ranges); (3) Decision Table Testing (604 parameterized orders); (4) State-Based Testing (drone navigation states); (5) Property-Based Testing (universal path properties); (6) Data-Driven (@MethodSource with REST endpoints); (7) Combinatorial (16 compass directions); (8) Random (@RepeatedTest(20) with Math.random()); (9) Negative (assertThrows for null/invalid inputs); (10) Dynamic (@TestFactory for polygon vertices).

\item\textbf{Adequacy criteria}: Statement coverage (all service methods executed, 97\% service coverage). Branch coverage 90\% (exceeds 75\% target). Method coverage 100\% for public APIs. Input domain coverage via systematic boundary testing. Path coverage through diverse polygon shapes. Use case coverage via end-to-end workflows. Data coverage with 604 distinct orders. Error coverage includes null pointer, illegal argument exceptions. Mutation coverage unmeasured (no PIT integration).

\item \textbf{Results}: 871 tests, 100\% pass rate, ~30s execution. Breakdown: ControllerTests (19, 0.21s), OrderValidationTests (604, 2.67s), LngLatHandlingTests (207, 0.58s), PathFindingTests (29, 23.5s), PathCalculationAsGeoJsonTests (12, 0.80s). Paths 104-232 steps, 1.3x-1.8x straight-line distance. JaCoCo: 85\% instruction (1911/2236), 90\% branch (189/208), 81\% line (357/438), 97\% service-level, 0\% controller.

\item \textbf{Evaluation}: 100\% pass rate shows functional correctness. 90\% branch coverage validates decision testing. 97\% service coverage indicates thorough business logic testing. Critical limitations: 0\% controller coverage (REST endpoints untested at HTTP level); only 49 positions versus thousands needed for statistical confidence; no performance benchmarking beyond binary timeout; absence of mutation testing makes assertion strength unknowable; concurrent scenarios untested; fault injection missing.
\end{enumerate}

\item \textbf{Evaluate the limitations of a given testing process, using statistical methods where appropriate, and summarise outcomes} \marginpar{[default 20\%]}
\begin{enumerate}
\item \textbf{Gap identification}: (1) No load/concurrent testing despite REST API nature; (2) Missing fault injection (network failures, malformed JSON, timeouts); (3) Insufficient spatial coverage: 49 positions = 0.49\% of 10,000 needed for 99\% confidence in no-fly zone avoidance; (4) No security testing (authentication, authorization, injection attacks); (5) Controller integration blocked by Spring Boot context conflicts (0\% HTTP coverage); (6) Undefined performance baselines preventing regression detection; (7) No mutation testing (assertion quality unverifiable); (8) Missing property-based frameworks (jqwik) for automated edge case discovery; (9) Cross-cutting concerns untested (logging, exception hierarchies); (10) Unexplored edge cases (close restaurants, destinations near no-fly boundaries).

\item \textbf{Target establishment}: Line coverage 95\% (safety-critical requirement; currently 81\%, -14\% gap). Branch coverage 90\% (ACHIEVED). Method coverage 100\% (ACHIEVED). Mutation coverage 75\% (UNMEASURED - PIT required). Performance: pathfinding <5s 95th percentile (EXCEEDED at 0.59s average, 8.5x margin), validation <100ms (UNMEASURED), coordinates <1ms (UNMEASURED). Reliability: zero no-fly violations in 10,000 simulations (INSUFFICIENT: only 49 tests, statistically insignificant), zero false negatives (UNVERIFIED), 99.9\% CI stability (UNKNOWN: no historical data).

\item \textbf{Target comparison}: Line 81\% vs 95\% target (-14\%). Branch 90\% meets target. Service 97\% exceeds expectations but controller 0\% creates void. Mutation unmeasurable vs 75\% - complete gap. Pathfinding 0.59s vs 5s provides 8.5x safety margin. Spatial 49 vs 10,000 yields 0.49\% coverage (99.51\% gap) - statistically insufficient for safety certification. Test stability untracked vs 99.9\% target. Gaps reveal intermediate maturity: functional correctness validated but quality attributes (trends, assertion strength, statistical confidence) largely unmeasured.

\item \textbf{Achievement roadmap}: (1) Fix Spring Boot @WebMvcTest configuration for MockMvc controller testing resolving 0\% coverage; (2) Integrate PIT mutation testing Maven plugin establishing 75\% baseline and identifying weak assertions; (3) Implement JMH benchmarks creating performance baselines enabling regression detection; (4) Expand PathFindingTests to 10,000 random coordinates achieving 99\% confidence; (5) Add WireMock for fault injection validating error handling; (6) Implement concurrent testing with ExecutorService validating thread safety; (7) Integrate jqwik for automated edge case discovery; (8) Add SLF4J with Logback validating logging completeness; (9) Establish Testcontainers for Docker-based integration testing; (10) Create performance monitoring dashboard tracking trends.
\end{enumerate}
