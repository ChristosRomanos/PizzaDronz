\section{Outline of the Software Being Tested}

PizzaDronz is a Spring Boot REST API for autonomous drone pizza delivery. The system validates orders (credit card, dates, restaurant availability), calculates optimal flight paths using A* algorithm while avoiding no-fly zones, and outputs paths as GeoJSON. Core components: LngLatService (coordinates, distances, regions), OrderValidationService (business rules, 604 real orders tested), AStarPathFinding (obstacle avoidance), and GeoJsonUtils (visualization). External data fetched via REST from restaurants, no-fly zones, and orders endpoints.

\section{Learning Outcomes}
\textit{This is the main part of the portfolio where you describe how you have gone about meeting each of the subcriteria.}
\begin{enumerate}
\item \textbf{Analyze requirements to determine appropriate testing strategies} \marginpar{[default 20\%]}
\begin{enumerate}
\item \textbf{Range of requirements}: Functional (distance calc, order validation, pathfinding), Quality (performance <60s, accuracy ±0.00015 epsilon), Safety (no-fly zone avoidance).
\item \textbf{Levels}: Unit (207 LngLat tests, boundary analysis), Integration (PathFinding with LngLatService), System (29 restaurants end-to-end with real API data).
\item \textbf{Test approach}: Boundary value analysis (MIN/MAX lng/lat), equivalence partitioning (valid/invalid ranges), decision tables (604 order combinations), property-based testing (path invariants: no-fly zones, central region, consistent distances).
\item \textbf{Assessment}: Appropriate for safety-critical system. Strengths: 604 real orders, boundary testing, property assertions. Limitations: Only 49 spatial positions (need 10,000), no concurrency testing, no fault injection.
\end{enumerate}
\item \textbf{Design and implement comprehensive test plans with instrumented code} \marginpar{[default 20\%]}
\begin{enumerate}
\item \textbf{Test plan}: Hierarchical structure with @Nested classes. 4 test classes: LngLatHandlingTests (7 nested groups), OrderValidationTests (604 parameterized), PathFindingTests (29 restaurants + 20 random), PathCalculationAsGeoJsonTests. Uses @TestInstance for shared setup, @BeforeAll for expensive REST calls.
\item \textbf{Quality}: 868 tests, 100\% pass rate, ~30s execution. Excellent: parameterized tests, data independence. Gaps: no explicit coverage criteria, no test prioritization, heavy REST dependency.
\item \textbf{Instrumentation}: JUnit 5 assertions with custom messages, ExecutorService timeout (60s), epsilon tolerance for floating-point, RestTemplate for integration, console output for performance, property invariants for paths.
\item \textbf{Evaluation}: Effective assertions/timeouts. Missing: JaCoCo coverage (NOW ADDED: 85\% instruction, 90\% branch), mutation testing, structured logging, per-test timing, memory monitoring.
\end{enumerate}
\item \textbf{Apply a wide variety of testing techniques and compute test coverage and yield according to a variety of criteria} \marginpar{[default 20\%]}
\begin{enumerate}
\item\textbf{Techniques}: (1) Boundary Value Analysis (MIN/MAX boundaries), (2) Equivalence Partitioning (valid/invalid classes), (3) Decision Tables (604 orders), (4) State-Based (drone navigation states), (5) Property-Based (path invariants), (6) Data-Driven (@MethodSource + REST), (7) Combinatorial (16 compass directions), (8) Random (@RepeatedTest(20)), (9) Negative (assertThrows).
\item\textbf{Adequacy}: Statement coverage (all service methods), Branch coverage (90\% with JaCoCo), Method coverage (all public APIs), Input domain (boundary analysis), Path coverage (geometric configs), Use case (end-to-end workflows), Data coverage (604 scenarios), Error coverage (exceptions).
\item \textbf{Results}: 868 tests, 100\% pass, ~30s execution. Pathfinding: 0.59s average, 1.3x-1.8x optimal path length. JaCoCo: 85\% instruction, 90\% branch, 97\% services, 0\% controllers. All 604 orders correctly validated. No timeouts.
\item \textbf{Evaluation}: Strengths: real data, property assertions, 97\% service coverage. Gaps: 0\% controller coverage (Spring context conflicts), no mutation testing, limited spatial coverage (49 vs 10,000), no fault injection, no concurrency tests.
\end{enumerate}
\item \textbf{Evaluate the limitations of a given testing process, using statistical methods where appropriate, and summarise outcomes} \marginpar{[default 20\%]}
\begin{enumerate}
\item \textbf{Gaps}: (1) No load/stress/concurrency testing, (2) No fault injection (REST failures), (3) Limited spatial coverage (49 positions vs statistical needs), (4) No security testing, (5) Controller layer untested (0\%), (6) No performance baselines, (7) No mutation testing, (8) No property-based frameworks (jqwik).
\item \textbf{Targets}: Line 95\%, Branch 90\% (MET), Method 100\%, Mutation 75\%. Performance: pathfinding <5s (MET: 0.59s), validation <100ms. Reliability: zero no-fly violations in 10,000 tests.
\item \textbf{Comparison}: JaCoCo integrated: 85\% instruction, 90\% branch (target met). Services: 97\% excellent. Controllers: 0\% (Spring conflicts). No mutation testing. Spatial: 49/10,000 (0.49\%). Performance targets met but not benchmarked.
